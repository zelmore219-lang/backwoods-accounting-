# Production connections

This adds background recording to the existing Backwoods Production application using the existing Employee owner service, Business Accounting company ledger, and Vendor catalog. Production keeps its current layout, navigation, recipe, manufacturing, packaging and release forms. There is no separate Production edition or replacement workflow. Production remains the source for recipes, material lots, batch costs and quality release. Employee owns account activation and application roles. Vendor owns packages after release; its deliveries record sales and cost of goods sold.

## Install and activate

1. Use Employee Windows **0.4.11**, Vendor **4.1.11**, Accounting **1.0.12** and Production Setup **1.0.2** for the combined Pest/Production release. These retain the existing Pest connection and company records. Back up your records, then use each existing app's App updates control to install the matching Employee, Vendor and Accounting updates under the same Windows account. Close Production and run **Backwoods-Production-Setup-1.0.2.exe**. Setup includes the original desktop launcher, Python and connection libraries, adds desktop/Start menu shortcuts, preserves the existing desktop database and saves previous application files in a dated backup. If WebView2 is missing, the bundled Microsoft bootstrapper installs it with an internet connection. Run Setup again for future Production reinstalls or upgrades.
2. Review the complete merged Firestore rules accompanying the Employee update against the current rules and publish the reviewed result in the existing project. Preserve rules added by later releases. This change adds protected stock revisions and operation receipts, plus the owner-private Production accounting source. It requires no new Firebase project or billing upgrade. The owner service verifies that the required stock protection is actually present before registering Production or sending inventory.
3. Start Employee's existing Windows **Owner service**. In **People → View → Application access**, grant actual staff **production** access: **production_manager**, **production_employee**, or **purchasing**. Confirm the access synchronization. Staff must be active, linked to their verified Firebase UID and using their personal changed password. A Production role does not grant Accounting or HR privileges.
4. Reopen the existing Production app, then run **CONNECT-EXISTING-APPS.cmd** from the installed **Application** folder for one-time setup (normally `%LOCALAPPDATA%\Backwoods Production\Application`). Verify the current Production manager and the existing Employee/Employer account, choose the actual existing Accounting owner for that legal company, and review the opening quantities/payables against the existing books. Resolve any overlap first; do not count previously recorded physical stock twice. One authoritative Production database is registered per company. A copied database cannot replace a newer published sequence.
5. Create each actual finished SKU in Vendor, stocked by **each** or **bag**. New lots released after connection match a single exact Vendor SKU in the background, using the batch's recorded package weight. A different package size needs its own SKU. If there is no unique matching SKU or the sizes disagree, Production retains the completed record and the stock waits for a reviewed mapping instead of transferring an inaccurate count. For stock already present at first connection, the setup command asks for an explicit MAP confirmation after checking those packages are not already included in Vendor. Rerun the setup command to review an old lot or missing SKU.
6. Continue the existing **Make a batch → Package & release** workflow. Unfinished production, bulk stock and packaged lots awaiting inspection do not transfer. Once the completed, packaged lot is inspected and **Released for sale**, the background connection queues the exact unreserved package count, clears those units from Production's available stock, and creates the warehouse-transfer journal. The original batch record stays in Production's history for traceability and costs. The existing **Integration queue** shows a saved retry until Vendor's atomic receipt is confirmed; it then shows **Received by Vendor**. Sell and deliver those packages from Vendor. Existing local reservations must be resolved/cancelled before their packages can transfer. Review recalls and post-transfer stock adjustments in Vendor.
7. Keep Production signed in as a manager, Employee Owner service online, and Business Accounting open. Operator changes remain locally recorded until a manager can send the queue. The worker retries automatically; the retained transfer/mailbox IDs and per-lot received capacity prevent duplicate receipts, including from an older restored copy of the same database. The original **Connections** page reports status only; routine Production work requires no new connection form or extra sync button. **Business Accounting → App connections → Backwoods Production** reports actual import success or the accounting review error.

The original standalone login remains available before connection. Once connected, Production uses Employee credentials and checks activation, password reset/revocation, company and application access for every request. Local Production passwords no longer authorize operational changes.

## Accounting behavior

The first reviewed connection records current material/WIP/finished inventory and supplier liabilities as opening balances. It preserves original source records and event history as supporting records; it does not fabricate missing historical journals, customer sales or bank payments. Opening values must be reconciled with already-recorded company balances before activation.

Subsequent event journals use integer cents and stable source IDs. Materials use 1240, WIP 1250 and Production finished goods 1260. Receipts accrue 2010 received-not-invoiced; approved matched supplier invoices reclassify that balance to Accounts Payable (2000). Approved supplier invoices and their outstanding balances appear in Accounting, where actual supplier payments can be recorded once and reconciled. Supplier returns reduce material inventory and establish a supplier credit receivable (1150), rather than inventing a cash refund.

Manufacturing transfers material cost through WIP to finished goods. Entered labor/overhead allocations credit 5930 Capitalized Production Cost Recovery; actual wage and expense postings remain in their existing sources and require the accountant's normal allocation review. Waste and valuation corrections use 5190. Recipe/schedule estimates do not post. A Vendor transfer moves 1260 to shared Vendor inventory 1200 without creating a purchase, sale or profit. Vendor receipts are supporting movements and are not capitalized twice. Actual delivered orders retain their historical COGS and sales postings in Vendor's existing feed.

Source snapshots include material lots, original supplier/receipt/invoice/batch records and the immutable Production event history. Existing closed-period, missing-posted-record, revision, balance and reconciliation protections remain enforced in Accounting. Confirm the Accounting import status; sending a snapshot alone is not confirmation of a posted ledger entry.

## Verification and boundaries

Automated domain tests exercise manufacturing, payables, cost conservation, held stock, transaction rollback, duplicate imports and access revocation. Real isolated Auth/Firestore emulator tests exercise Production's native sign-in, encrypted Employee mailbox, original company selection, release receipt, a lost response followed by retry, Accounting retrieval/import, changed-ID payload rejection and revocation of an open session. Firestore rules tests cover old clients, receipt deduplication, concurrent receipt/delivery and owner-private financial data. Browser checks use the original packaging, inspection and release forms, then verify desktop/tablet/phone screens, the cleared Production stock, retained batch history and actual Vendor receipt.

These are disposable fixtures, not live company records. No live company rule, employee permission, stock, ledger or updater feed is changed by the tests. The published Production 1.0.1 installer, Employee Windows 0.4.10, Vendor 4.1.11 and Accounting 1.0.12 passed native installation/upgrade acceptance. Vendor and Accounting Android packages also passed signed release upgrade tests. The release evidence identifies each accepted source and package hash.

The current encrypted bridge supports a 12 MB complete Production snapshot. Oversized snapshots remain local and show an error; they are not partially published.
